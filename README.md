# SMASH V15.6 · Rookie Pathway & Tournament Flow

女子单打球员生涯模拟游戏。V15.6 扩展 S300 资格赛与新秀晋升通道，调整模拟操作入口。V15.5 新增单场赛果反馈、整站赛事模拟与左右手专项标定。V15.4 优化反手接杀、转体与回位动作，女单统一使用高远发球，精简临场交互。V15.3 修复判罚回放并新增生涯技术与空间报告，在 V15.2 赛前备战、技术统计与观赛交互的基础上迭代，继承 V15.1 比赛平衡和战术智能；保留 100 名球员数据库、原赛历、3×15（21 分封顶、8 分间歇）规则、场馆、人物动画、职业生涯与存档体系。游戏结果和属性均为模拟，不代表真实运动员预测。

## 启动

- GitHub Pages：把本压缩包内的内容完整解压到仓库根目录，保留目录层级及 `.nojekyll`，启用 Pages 后通过 HTTPS 打开。
- 本地：在解压后的 `index.html` 所在目录运行 `python -m http.server 8000`，浏览器打开 `http://localhost:8000`。不要直接双击 HTML。
- 首次启动需要连接 `cdn.jsdelivr.net` 下载 Pyodide 0.27.7；其余运行文件随本包提供。建议使用 Chrome / Edge / Firefox。
- 存档：保留原 IndexedDB 键和生涯版本标识，支持原版女单存档。升级前请导出 JSON 备份。旧比赛记录不重算，正在进行的比赛将从下一分使用新引擎；旧存档无新增战术状态时从空状态开始学习。

## V15.6 修改（当前版本）

- S300 游戏扩展规则：正赛仍为32签位；24名直接入围，8个资格赛通道，每通道最多8人，最多64名资格赛选手、合计88名入围球员（旧版44名）。有效报名不超过32人时直接进入正赛。资格赛人数超过32时增设Q3，首日Q1/Q2，次日Q3/R32，最多两场实战/日，保留场间恢复。其余级别原规则不变。
- 排名仍优先。若有效报名超过88名，最多4个资格赛席位可由原排名截线以外、过去84天内在实际模拟赛事中取得S100冠军或亚军积分的球员优先获得；未使用名额按排名分配。适用于所有球员，无自动正赛或保送冠军。扩展资格赛前两轮出局且实际参赛获320分，Q3出局获660分（BWF84游戏积分表）；晋级正赛后仅结算正赛积分。资格赛与正赛不重复累计本站排名积分。这是游戏自定义准入扩展，并非现实BWF官方赛制。
- 仅新关闭报名的S300采用新规则，已经接受报名或已经抽签的旧赛事保留旧规则、签位及赛程，不强制重开档。
- 测试：世界排名101的新建球员（CA75）在8个随机种子、2027年8站S300的64次独立初始报名对照中，旧版0次入围、新版64次入围（有效报名56–78名；不等同于连续赛季实际参赛率）。验证31/32/33/40/56/57/65/72/88/101名报名情形及成绩优先通道。完整88人赛事87场快速引擎比赛完成，含资格赛中途存档恢复、32名正赛球员、每日最多两场及积分不重复验证。

## V15.5 修改（历史）

- 单场赛果弹窗：最后一分的动画及判罚回放结束后显示；直接结算比赛时立即显示。小组赛仅提示胜利/失败，淘汰赛提示晋级/淘汰，决赛胜利显示夺冠。列出各局比分，支持继续及赛后报告；历史回放不会重复弹出结果。
- 赛前/观赛设置、更多操作和赛事页增加「模拟至本站赛事结束」。已开始比赛沿用其原引擎，未开始比赛采用快速代理；不生成虚构空间轨迹。即使个人提前出局，也推进本站余下签表至正式结算。其他报名截止仍暂停，确认报名或休赛后继续；取消报名弹窗可退出批量模拟。整站批量操作只显示本站最终总结，避免逐场弹窗阻塞。
- 横向击球误差、接球预判偏差、候选落点搜索、局部优化与微小战术扰动采用持拍手相关方向，避免固定坐标方向对左右手产生系统性偏置。保持原有击球几何、战术克制、反手防守机制和高远发球规则。

- 快速引擎：160 分训练和 160 分独立留出。旧手别系数、岭回归拟合手别系数均未胜过零手别附加项的留出表现（旧/零手别项 Brier 0.2490/0.2472，log loss 0.6913/0.6875）。因此删除三个手别附加胜率项，保留属性、身高、发球权和 V15.4 回合模板。异手/同手仍可使用不同回合模板；不增加左手固定加成。快速引擎 600 场镜像测试（每种手别组合 150 场）通过；异手组合交换左右手后同种子结果相同。
- 原生 Python 生涯测试：完整结算 63 个签表对阵的赛事，重复结算防护及存档恢复通过；单场结算通过。Chromium 使用原生 Python 状态与结果注入，测试赛前设置、观赛设置、结果弹窗各阶段标签、动画完成门控、手机布局及整站结果页。当前环境未执行公网 Pyodide 端到端测试。
- 修正赛前近期战绩说明为「最近一场在右」。

## V15.1 修改

### Engine Balance

- 缓和整体能力差在移动、预判、击球等多个环节中的重复增益，同时保留专项技术差异，未直接按排名、CA、球员身份控制胜负。
- 快速模拟代理改用新版空间引擎真实模拟样本：40 组、640 回合，480 用于训练、160 按对阵组留出。正则化拟合属性、状态、体能、发球与体型相关特征；模板根据相对属性、绝对能力、手别、身高、疲劳、状态、发球方及结果进行条件抽样。没有伪造空间轨迹。仍为近似引擎，并非每一分重新执行空间物理。
- 修复预计发球出界优先于已成功接发触球的判罚顺序；无成功触球时仍按实际落点判罚。未扩展到全部现实发球动作违例。
- 高质量、准备充分且技术条件满足时可考虑真正反手点杀/重杀，仍受拍面几何和降低的出球功率、增加的误差限制。放网连续争夺的额外惩罚减弱，避免不必要地压制网前球路。
- 提高实际执行风险的决策惩罚。加入等 CA 风格控制组构造函数，测试不再混淆风格和属性总量。

### Tactical Intelligence

- 发球类型和横向落点基于候选弹道、接发预测、第三拍机会、失误风险及带先验收缩的发球历史选择，不再固定概率；玩家短发/高远偏好只是权重。
- 在原有两层候选预测及第三次触球机会评估上，加入跨拍战术意图：高球后找前场、前场球后找后场、反手压制、终结、恢复或打空当。意图为连续效用项，不强制击球序列。
- 跨回合记录双方近期胜率、非受迫失误、对手球路、发球表现和负荷；自适应模式根据表现调整策略，手动模式保持玩家指定的策略。
- “我的战术”区分自适应与真正均衡，新增反手后场/追身、击球风险、回合节奏、回位重心。设置在下一分生效；所有偏好通过候选落点、效用和回位执行，不直接改变胜率。显示上一分实际打法；近期建议使用最多24分数据，并提高样本门槛。
- 战术状态通过 JS–Python 桥接写入 active match 存档，旧存档缺字段时自动初始化。

`data/runtime-manifest.json` 将已分类的 Python 源文件映射至 Pyodide 虚拟文件系统中的原模块路径，所以原导入及数据路径保持不变。不要单独移动分类文件而不更新清单。若做原生 Python 调试，按清单将每个 `url` 复制至临时目录的 `path`，再从该目录导入 `web_adapter`，而非直接从分类目录启动。原版多代测试样本、旧报告、历史渲染测试 HTML、缓存等未进入发行包；兼容模块仍被运行清单及导入链引用，保留。
