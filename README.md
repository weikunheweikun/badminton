# SMASH V15.4 · Backhand Defense & Match Flow

女子单打球员生涯模拟游戏。V15.4 优化反手接杀、转体与回位动作，女单统一使用高远发球，精简临场交互。V15.3 修复判罚回放并新增生涯技术与空间报告，在 V15.2 赛前备战、技术统计与观赛交互的基础上迭代，继承 V15.1 比赛平衡和战术智能；保留 100 名球员数据库、原赛历、3×15（21 分封顶、8 分间歇）规则、场馆、人物动画、职业生涯与存档体系。游戏结果和属性均为模拟，不代表真实运动员预测。

## 启动

- GitHub Pages：把本压缩包内的内容完整解压到仓库根目录，保留目录层级及 `.nojekyll`，启用 Pages 后通过 HTTPS 打开。
- 本地：在解压后的 `index.html` 所在目录运行 `python -m http.server 8000`，浏览器打开 `http://localhost:8000`。不要直接双击 HTML。
- 首次启动需要连接 `cdn.jsdelivr.net` 下载 Pyodide 0.27.7；其余运行文件随本包提供。建议使用 Chrome / Edge / Firefox。
- 存档：保留原 IndexedDB 键和生涯版本标识，支持原版女单存档。升级前请导出 JSON 备份。旧比赛记录不重算，正在进行的比赛将从下一分使用新引擎；旧存档无新增战术状态时从空状态开始学习。

## V15.4 修改（当前版本）

- 近期战绩由左至右按时间排列，最近一场在最右侧；后端仍保留原历史顺序，兼容旧存档。
- 女单固定选择正手高远发球，仍根据接发难度、风险及第三拍机会选择横向落点；取消发球类型偏好、比例和相关战术建议。短发球轨迹和动画代码保留，仅用于旧存档回放。旧存档中的发球偏好不再参与比赛决策。
- 临场战术按钮改为显示当前配置，取消基于小样本的实时推荐与自动弹出战术窗口。手动战术控制、赛前报告及球员自身自适应决策保留；不再强制暂停以等待调整。
- 反手击球的身体转角随接触点相对位置变化。随挥方向参考实际出球方向，躯干与骨盆在击球后连续过渡到移动姿态；反手过顶恢复窗口约 0.58 s，紧凑反手约 0.38 s，受后续动作覆盖。击球瞬间仍使用引擎提交的触球几何和拍面。
- 反手快速防守在可达范围内比较不同步位，优先可执行、不过度伸展且移动成本较低的接触位置；缩短紧凑反手换握准备时间，实际接球和战术预测共用此机制。未增大球拍或直接提高反手胜率，仍有挥空、到位失败、回球失误及疲劳限制。
- 后台快速代理用 40 组、480 分新版空间样本重新标定（360 分训练，120 分按对阵组留出），所有回合模板均为高远发球。留出 Brier 误差 0.2052（旧模型在同一批数据上 0.2073）。代理仍为统计近似，不代表真实运动员数据。
- 受控测试：重杀来球正反手侧各 576 次（镜像手别、多个站位与落点、固定种子），旧版反手侧成功接触 530/576，新版 576/576；正手侧均为 576/576。仅为该受控工况的接触率，不等于实际比赛回球成功率或得分率。

## V15.3 修改

- 修复自动下网与近线判罚回放访问已删除状态栏导致帧循环中断的问题。回放绘制失败时跳至分间阶段，帧循环具有异常保护，不重新结算比赛。
- 球员档案新增生涯技术统计、制胜球落点与场区占位热力图；每场完赛保存 6×8 网格及技术汇总，独立于回放轨迹的裁剪规则。空间图基于真实模拟记录，场区占位为停留时间而非脚步次数。
- 赛前新增双方最近 10 场正常完赛的技术与空间报告，以及有样本门槛的战术参考。报告标注技术和空间样本覆盖率；不同图的色阶独立。后台比赛无空间记录时不伪造；旧存档迁移时仅恢复尚存的日志和汇总，已被裁剪的轨迹无法恢复。
- 统一界面用语：职业生涯、能力发展、参赛计划、制胜分、接发球回合、场区占位、回放等。保留 V15.1 比赛引擎与原存档格式兼容性。

## V15.2 修改

- 移除画布下方实时状态栏，保留场内记分牌、得分判罚浮层以及主要比赛按钮。战术按钮直接显示当前推荐策略。
- 技术统计以双方共用的 PK 条对比总得分、主动得分、失误、发接发和长短回合胜率、移动距离；移除各球种使用率和折叠式详细栏目。条形比例为两项实际数值相对占比，0:0 或无数据使用灰条。失误和移动距离的较高数值不代表表现更好。
- “空间热力图”标签：使用实际记录的直接得分场内终结落点，以及每约 0.12 秒采样的球员位置停留时间（不是脚落地次数）。换边后统一坐标；同类双方共用色阶，不计场外位置。缺少轨迹时明确提示，不生成假数据。
- 回看按钮可选择最近三分内任一有轨迹的已结算回合；回放使用原记录和历史比分，不重新模拟或改写存档。旧比赛仅保留汇总数据时不可回看。原有存档裁剪策略不变。
- 新的赛前备战页面显示生涯交锋胜场、本季及近10场胜率、近期战绩和最近5次交锋，数据来自本存档的已完赛记录；近10场和交锋排除退赛、轮空和弃权。本赛季胜率沿用赛季统计口径。赛前推荐与六项战术参数直接呈现，确认后通过原战术 RPC 保存并开赛。没有新增真实世界历史数据。
- 赛中技术统计和战术采用平铺布局及两项统计标签，避免多级折叠。保留旧版比赛引擎、数据、存档键和运行文件目录；V15.2 不改变 V15.1 的物理和胜率标定。

## V15.1 修改

### Engine Balance

- 缓和整体能力差在移动、预判、击球等多个环节中的重复增益，同时保留专项技术差异，未直接按排名、CA、球员身份控制胜负。
- 快速模拟代理改用新版空间引擎真实模拟样本：40 组、640 回合，480 用于训练、160 按对阵组留出。正则化拟合属性、状态、体能、发球与体型相关特征；模板根据相对属性、绝对能力、手别、身高、疲劳、状态、发球方及结果进行条件抽样。没有伪造空间轨迹。仍为近似引擎，并非每一分重新执行空间物理。
- 修复预计发球出界优先于已成功接发触球的判罚顺序；无成功触球时仍按实际落点判罚。未扩展到全部现实发球动作违例。
- 高质量、准备充分且技术条件满足时可考虑真正反手点杀/重杀，仍受拍面几何和降低的出球功率、增加的误差限制。放网连续争夺的额外惩罚减弱，避免不必要地压制网前球路。
- 提高实际执行风险的决策惩罚。加入等 CA 风格控制组构造函数，测试不再混淆风格和属性总量。

### Tactical Intelligence

- 发球类型和横向落点基于候选弹道、接发预测、第三拍机会、失误风险及带先验收缩的发球历史选择，不再固定概率；玩家短发/高远偏好只是权重。
- 在原有两层候选预测及第三次触球机会评估上，加入跨拍战术意图：高球后找前场、前场球后找后场、反手压制、终结、恢复或打空当。意图为连续效用项，不强制击球序列。
- 跨回合记录双方近期胜率、非受迫失误、对手球路、发球表现和负荷；自适应模式根据表现调整策略，手动模式保持玩家指定的策略。
- “我的战术”区分自适应与真正均衡，新增反手后场/追身、击球风险、回合节奏、回位重心。设置在下一分生效；所有偏好通过候选落点、效用和回位执行，不直接改变胜率。显示上一分实际打法；近期建议使用最多24分数据，并提高样本门槛。
- 战术状态通过 JS–Python 桥接写入 active match 存档，旧存档缺字段时自动初始化。

```

engine/python/core/       公共属性、体能及基础模型
engine/python/match/      比赛与快速模拟标定数据
engine/python/career/     生涯、成长、生命周期
engine/python/competition/ 赛历、报名、资格、抽签和排名
engine/python/management/ 相关经营及兼容模块
data/                     球员、赛历、运行文件清单
```

`data/runtime-manifest.json` 将已分类的 Python 源文件映射至 Pyodide 虚拟文件系统中的原模块路径，所以原导入及数据路径保持不变。不要单独移动分类文件而不更新清单。若做原生 Python 调试，按清单将每个 `url` 复制至临时目录的 `path`，再从该目录导入 `web_adapter`，而非直接从分类目录启动。原版多代测试样本、旧报告、历史渲染测试 HTML、缓存等未进入发行包；兼容模块仍被运行清单及导入链引用，保留。

## 验证记录与边界

- 旧版 7 场（339 分），新版 14 场（685 分）独立完整空间比赛测试，使用生涯属性预处理及等 CA 风格控制组。另有 640 分用于重新标定和留出验证；留出集 Brier 误差 0.1845→0.1779，log loss 0.5525→0.5312（越低越好，旧系数对照）。
- 新版完整比赛单分胜率：均衡85/85 54.1%；73/97 14.3%；97/73 93.8%；80/90 27.7%；90/80 66.7%；等CA进攻/防反 52.8%；等CA拉吊/网前 45.8%。每组2场，样本不足以精确排名或证明完全平衡。
- 后台快速引擎另跑500场（每组100场）；73/97、80/90、85/85、90/80、97/73 的 A 单分胜率分别为10.18%、29.04%、50.06%、70.92%、89.71%，平均拍数分别7.36、8.43、9.28、8.40、7.33。
- 独立发球偏好实验：各16次固定种子强制由A发球，短发优先2次高远、自动5次高远、高远优先13次高远。该实验验证偏好传导，不代表实战获胜收益。
- 504项弹道约束、504项镜像姿态/方向性检查、1210帧替代Canvas投影检查通过。原生 Python 与实际 Node 空间桥接通过：生涯开档、报名、推进赛事、战术RPC、首分、存档续算确定性、新旧字段迁移，以及快速引擎存档续算。
- 当前测试环境限制真实浏览器网络导航和 CDN 运行时访问，未完成部署环境完整端到端及多赛季压力测试；战术参数、反手攻击频率和真实比赛统计仍需进一步验证。两套引擎虽重新标定，但不保证逐分一致；快速引擎不模拟手动临场策略。
